# Project History
The development history of FLIM Playground is interesting in its own right and, hopefully, shares common traits with other “platform-y” projects. By jotting down a few memorable milestones here, I want to remind myself and others that all of the architectural decisions grew out of synthesizing diverse needs by coming up with meaningful abstractions. The needs are specific, **data-driven**, and from them abstract hypothesis are constructed (**hypothesis-driven**), which will in turn place constraints on the way the data is read and processed. This feedback loop is neither top-down—where a hypothesis dictates data analysis or even collection—nor bottom-up—where fragmented code snippets address isolated needs. Instead, it reflects a more sustained way of doing research (because loops by definition go indefinitely), which is precisely the type of research that FLIM Playground aims to facilitate. I am proud that it has been developed to try to exemplify this approach.

It starts from the very specific need of identifying single-cell outliers in UMAP. 

## Milestone 1 – Early Architecture (Dec 2024)
**Conceptual shift:** turn ad-hoc FLIM scripts into a deployable Streamlit workbench with navigable workflows.
- `f30a795` (2024-12-06) seeded `main.py` with the PCA-based outlier explorer: a CSV uploader, NADH/FAD/morph multiselects wired to the uploaded columns, the exact `StandardScaler → PCA` pipeline from scikit-learn, and a Plotly scatter colored by `treatment`, so the first Streamlit view already looked like the later playground pages.
- `8e08d2a` (2024-12-10) moved that logic into `pages/outlier_finder_fit.py`, leaving `main.py` to focus on navigation. That commit is where the `pages/` convention and per-page Streamlit session state started.
- `397446e` (2024-12-12) expanded the feature into today’s multi-method QC: `pages/outlier_finder.py` now imports `dimension_reduction.py` to share PCA/UMAP code, injects `navigation.render_top_menu()`, builds session-state-controlled dropdowns (the `reset_other_menus` callback) for image-level boxplots, and renders Seaborn/Plotly clusters with hover text sourced from `base_name`.
- `6ac3fa3` (2024-12-15) extracted a reusable filtering surface into `widgets.py`—the `create_filters` helper plus the `update_multiselect` callback that enforces “All” logic—while renaming `environment.yml` to `conda_environment.yml` so Streamlit Cloud would honor `requirements.txt`. Later pages reuse that widget to filter experiments/cell lines without duplicating code.

## Milestone 2 – FP 2.0 Modular Feature System (Mar 2025)
**Conceptual shift:** redesign every feature to flow through declarative feature groups, reusable UI components, and richer classifiers—“FP 2.0”.
- `8d852ed` (2025-03-25) replatformed navigation: `navigation.py` now autogenerates the top menu from page names, `docs.py` carries Markdown snippets per playground, and `main.py` renders the logo plus a doc panel entirely from those data structures—clearing out the bespoke markdown scaffolding for FP 2.0.
- `05c3fce` (2025-03-25) codified feature metadata in `feature_groups.py` (ordered group list, default columns, prefixes) and taught `features.py` to return tuples of NADH/FAD/morph/distribution/fit-free columns, drop NaNs, and synthesize `image_name` from `cell_id`. `pages/visualization.py` now calls `check_and_fix_df`/`get_features`, feeds the result into `create_singleSelects_vars`, and pipes it to `feature_comparison_plot`—turning “feature choice” into data rather than if/else trees.
- `f27e610` (2025-03-26) deleted the catch-all `widgets.py` and replaced it with `filter_widgets.create_filters` (build one multiselect per categorical column, track “All” via `update_multiselect`) and `selection_widgets.create_singleSelects_vars/create_multiSelects_vars`, plus helper callbacks for mutually exclusive dropdowns and UMAP hyper-parameters. Visualization/cluster pages immediately import those helpers instead of embedding UI logic.
- `c1307d4` (2025-03-26) finished the widget modularization by moving everything under `widgets/` (`custom_widgets` for UMAP inputs, `outlier_removal_widgets` for cell/image toggles, `selection_widgets` for feature pickers) and updating each page to consume them; the shared widget modules now determine column layout (one Streamlit `st.columns` group per feature group) instead of per-page ad hoc grids.
- `b437157` (2025-03-27) rebuilt `pages/classification.py` on top of the new widgets: `widgets.load_data_widgets.load_csv` caches uploads and returns `(df, feature_cols_dict)`, `filters_widget` combines arbitrary categorical columns into a `classes` column, `multi_feature_select_widget` enforces layout-aware multiselects, and the page now generates “one class vs the rest” options before dispatching to `train.classify` with the selected algorithm and train/test split.

## Milestone 3 – Channel-Level + Analysis Config Era (Jul–Sep 2025)
**Conceptual shift:** drive the app from configuration, linking metadata ingestion, analysis recipes, and channel-aware acquisition settings.
- `b23a1ca` (2025-07-09) turned `main.py` into an interactive config editor: it now loads/saves `config.toml`, lets users set `num_channels`, rename channels, pick feature types per channel, and edit every required file suffix. The accompanying `config.toml` captures `required_file_types`, `inputSuffixes`, and `feature_types`, so all later modules (via `src.config`) pull canonical values from one file.
- `21931b0` (2025-07-10) rewrote `pages/data_extraction.py` into the three-step wizard that still exists. It now calls `src.config.get_channel_names/get_num_components/get_feature_types`, renders suffix pickers via `src.widgets.metadata_widgets.load_data_suffix_widget`, uses `check_assign_channel_widget` to map raw channels to decay files, and exports metadata with `export_metadata_widget`—all backed by the config file authored on the main page.
- `bfee8d4` (2025-07-26) introduced `analysis_config.toml` plus `src/widgets/analysis_config_widgets.dataset_config_widget`, which syncs `unique_row_id_col`, `fov_name_col`, categorical lists, and numeric extractor groups between Data Extraction and Analysis. `src/dataset_io.py` now uses those settings to fuzzy-match categorical headers, preserve only configured columns, and group numeric features by extractor/channel before `pages/data_analysis.py` renders plots.
- `40c65fc` (2025-08-20) completed the reference-dye-aware pipeline: `src/file_io.get_decay_curves` samples decay curves per FOV (with `_get_sample_decay_curves` rejecting saturated traces), `get_irf` fetches channel-specific IRFs, `src/metadata.py` validates `reference_dye_file/reference_dye_lifetime` when fit-free calibration is set to “Reference Dye”, and `src/fov_extraction.py` now computes intensity texture/morphology features (`granularity`, `radial_distribution`, `mass_displacement`) alongside lifetime fits so calibrated data and extracted features share the same metadata frame.
- `edab183` (2025-09-03) expanded the config to channel-specific imaging modes: `config.toml` now defines an intensity-only channel (`ch3`) with its own input type (`Intensity (2D)`) and suffixes, while `src/widgets/metadata_widgets.load_data_suffix_widget` loops per `(channel,input_type)` to request the correct suffixes (auto-generating SPCImage `t1/t2` names from the `a1` suffix). `pages/data_extraction.py` and the metadata widgets honor those per-channel imaging modalities so FLIM and epi/confocal-only channels coexist inside the same metadata+analysis configs.
